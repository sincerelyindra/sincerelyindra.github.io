01

Project scope

I reimplemented the 124M-parameter GPT-2 decoder in PyTorch, covering masked multi-head attention, residual connections, layer normalization, and tied embeddings. I loaded the official checkpoint and verified numerical agreement with Hugging Face logits, then built autoregressive generation and domain fine-tuning pipelines using cross-entropy loss, AdamW, learning-rate scheduling, and mixed-precision training. 02

Inside the decoder

Token and learned position embeddings form the input representation. Twelve decoder blocks transform it; a final layer normalization and vocabulary projection produce a next-token logit vector at each position. The output projection shares its weights with the token embedding table. [2] [3]

03

Attention without looking ahead

The 768 channels split into 12 heads of width 64. Each head projects queries, keys, and values. A query at position i may attend to keys at positions j ≤ i, including itself; future positions are masked before softmax. [4]

Attention=softmax(QK⊤64+M)V

Mij = 0 when j ≤ i; Mij = −∞ when j > i.

04

Where the 124M parameters live

Using the canonical dimensions and counting each shared tensor once gives 124,439,808 unique parameters. The largest component is the MLP stack. Tying the vocabulary projection to the token embedding avoids a second 50,257 × 768 matrix. [2] [1]

05

One objective, two uses

A causal language model learns to predict the next token from the available prefix. Domain fine-tuning continues this objective on domain text; generation uses the resulting distribution to append one token at a time. Both pipelines are documented in the project summary. [P] [3]

Documented training components

Cross-entropy
Compares unnormalized vocabulary logits with next-token target IDs. An extra softmax is not needed before PyTorch’s loss. [5]
AdamW
Adaptive optimization with decoupled weight decay. [6]
Learning-rate scheduling
Changes the learning rate over training. The project summary does not specify the schedule or its settings.
Mixed precision
Uses different floating-point precisions for suitable operations. The chosen dtype and hardware are not specified in the summary. [7]
06

Checking the reconstruction

Loading a checkpoint tests whether the reconstructed architecture is compatible with the pretrained model. The project summary reports numerical agreement between the custom implementation and Hugging Face logits after loading the official GPT-2 checkpoint. [P]

Reported verification

Checkpoint-loaded logits agree with the reference.

The summary provides no numerical tolerance, comparison log, or maximum-error value. This page reports the verification claim at that level.

Why weight layout matters

In Karpathy’s reference loader, GPT-2’s Conv1D-style projection weights are transposed when copied into PyTorch Linear layers. This affects the attention QKV and output projections, and both MLP projections. Matching tensor sizes alone is insufficient if the orientation is wrong. [1]

A controlled logit comparison uses identical token IDs, position handling, checkpoint weights, and evaluation behavior. This describes the verification principle; the supplied summary does not contain the project’s test code.
